# 安装、启动与「退出」机制说明

> 建立时间：2026-11-03　适用版本：0.2.46+（含缺陷审计修复）
> 本文只写本机实测过的路径与行为，未验证的内容标注为「待核实」。

## 一、三个目录，各管一件事

| 目录 | 路径 | 作用 |
| --- | --- | --- |
| 源码仓库 | `C:\Users\eric8\.dsh\plugin-src\dsh-fish-pet` | 开发、提交、推 Gitee |
| 安装目录 | `C:\Users\eric8\.dsh\profiles\web\node_modules\dsh-fish-pet` | 鱼的进程实际加载这里 |
| 运行目录 | `C:\Users\eric8\.dsh\fish-pet` | 配置、日志、存档、MIDI、谱图 |

启动器 `运行目录\fish-pet.vbs` 里写死了安装目录的绝对路径：

```
powershell.exe -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden
  -File "C:\Users\eric8\.dsh\profiles\web\node_modules\dsh-fish-pet\assets\fish-pet.ps1"
```

**启动器指向哪，鱼就从哪加载**——改源码仓库不会影响正在运行的鱼，必须把文件复制到安装目录才算部署。

## 二、安装目录可能消失（2026-11-03 实际发生）

2026-11-03 的 DSH 启动调优中，`dsh-fish-pet` 被 `dsh plugin --profile web remove` 卸载（原因见 `~/.dsh/AGENTS.md` 2.8 节：其 `lib/index.js` 把 `enabled` 硬编码为 `true`，禁用开关无效；桌宠 + TTS + ASR 常驻约 341MB）。

后果：

- `profiles\web\node_modules\dsh-fish-pet` 整个目录被删除
- `profiles\web\package.json` 中的 `dsh-fish-pet` 依赖被移除
- 启动器仍指向旧路径 → 双击 vbs 无反应，鱼不出现

**恢复方法（实测可用）**：

```powershell
$pkg  = "C:\Users\eric8\.dsh\plugin-src\dsh-fish-pet"
$plug = "$env:USERPROFILE\.dsh\profiles\web\node_modules\dsh-fish-pet"
New-Item -ItemType Directory -Force -Path $plug | Out-Null
Copy-Item "$pkg\*" $plug -Recurse -Force -Exclude '.git'
Remove-Item "$env:USERPROFILE\.dsh\fish-pet\pet.pid","$env:USERPROFILE\.dsh\fish-pet\pet.quit" -Force -ErrorAction SilentlyContinue
Start-Process explorer.exe "$env:USERPROFILE\.dsh\fish-pet\fish-pet.vbs"
```

这样恢复的是**独立进程形态**：鱼能正常跑、能说话、能弹琴，但**不再是 DSH 的插件**（不影响聊天窗口，也不需要它）。

若要让 DSH 重新把它当插件加载，需要 `dsh plugin --profile web add <路径或仓库地址>` 再重启 dsh web——**这一步未在本机验证过**，且会重新引入 AGENTS.md 2.8 记录的启动耗时与内存占用，需权衡。

## 三、「让它游走（退出）」为什么以前关不掉

### 旧行为（已修）

```
点退出 → 删 pet.pid → 关窗
宿主 lib/index.js 每 10 秒检查：pid 文件不在 → 重新 spawn
结果：10 秒后鱼自己回来了，用户以为关不掉
```

### 新机制

在运行目录写一个 `pet.quit` 标志文件：

```
点退出 → 写 pet.quit → 删 pet.pid → 关窗
宿主守卫：发现 pet.quit 存在就跳过重启
下次正常启动：主脚本启动时删掉 pet.quit，恢复自动拉起
```

涉及两处代码：

- `assets\fish-pet.ps1`：启动时清 `pet.quit`；退出时先写 `pet.quit` 再写 `asr.stop`
- `lib\index.js`：`QUIT_FILE` 常量 + 守卫里 `if (existsSync(QUIT_FILE)) return`

**注意**：`lib\index.js` 的改动在安装目录里，**重装插件会被覆盖**。独立进程形态下这段代码不参与运行（没有宿主），所以也不影响。

### 想重新让鱼被自动拉起

删掉标志即可：

```powershell
Remove-Item "$env:USERPROFILE\.dsh\fish-pet\pet.quit" -Force
```

## 四、日常改代码后的部署命令

```powershell
$pkg  = "C:\Users\eric8\.dsh\plugin-src\dsh-fish-pet"
$plug = "$env:USERPROFILE\.dsh\profiles\web\node_modules\dsh-fish-pet"
Copy-Item "$pkg\assets\fish-pet.ps1"        "$plug\assets\fish-pet.ps1" -Force
Copy-Item "$pkg\assets\asr-listener.ps1"    "$plug\assets\asr-listener.ps1" -Force
Copy-Item "$pkg\assets\lib\*.ps1"           "$plug\assets\lib\" -Force
Copy-Item "$pkg\assets\data\culture\*.json" "$plug\assets\data\culture\" -Force
```

然后重启鱼（先杀进程、删 pet.pid、再跑 vbs）。

## 五、踩过的坑（都实际发生过）

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 鱼突然消失、双击 vbs 无反应 | 安装目录被卸载 | 按第二节重建 |
| 鱼起不来、无日志 | 改了菜单项定义却留下事件绑定（`$miStory.Add_Click` 指向已删变量） | 删残留绑定 |
| 鱼起不来、语法检查却通过 | 括号错位（`if ($x) { ... }` 被合并成一行后多出一个 `}`） | 语法检查 + 真启动双验证 |
| 改完没生效 | 改的是源码仓库，没复制到安装目录 | 按第四节部署 |
| 目录里有 2540 行的 `fish-pet.ps1` | 早期版本残留的僵尸副本 | 已改名 `*.stale`，见运行目录 `僵尸文件说明.txt` |
